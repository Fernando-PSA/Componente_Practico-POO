## Architecture

Layered CLI application for event management with JSON persistence:

```
app.py              ← CLI menu system (presentation layer)
services/           ← Business logic + CRUD per entity
repository/         ← Single JSON repo (repo_json.py) — all DB access goes through here
models/             ← Plain data classes with convertir_a_diccionario() for serialization
utils/              ← validaciones.py (all user input), generador_id.py (sequential IDs)
data/db.json        ← Persistent store; auto-created on first run if missing
```

**Entities:** `evento`, `organizador`, `venue`, `patrocinador`, `asistente`, `entrada` (ticket)

**Relationships:** events hold `organizador_id`, `venue_id`, and `patrocinadores_ids` (list); entradas hold `evento_id` and `asistente_id`.

## Key Patterns

**Soft delete:** All entities have an `estado: bool` field. Never hard-delete — use `repo.eliminar_logico(coleccion, id)` which sets `estado = False`. Most `listar`/`buscar` calls pass `solo_activos=True` by default.

**Referential integrity:** Services check for dependent records before allowing deletion (e.g., can't delete an organizer that has events). Follow this pattern when adding new relationships.

**Input validation:** All interactive input goes through `utils/validaciones.py`. Functions return the validated value and accept an optional `actual=` parameter for update flows. Add new field types here rather than inline in services.

**Retry loops:** Services use `while True` loops with labeled break conditions (comments like `# 🔄 BUCLE 1` / `# 🏁`) for interactive flows that need re-prompting on invalid input.

## Business Rules

- Events require a venue from the same city and at least one sponsor.
- Venue minimum capacity: 100. Sponsor minimum aporte: $10,000.
- Entradas service enforces remaining seat capacity before issuing tickets.
- Dates use `dd/mm/yyyy` format; only year ≥ 2026 is accepted.
- Ecuadorian cedula (10-digit) is validated with the province-code + checksum algorithm in `validaciones.py`.

## Data

`data/db.json` contains 6 collections: `organizadores`, `venues`, `patrocinadores`, `asistentes`, `eventos`, `entradas`. Pre-populated with sample data for manual testing. IDs are sequential integers generated by `utils/generador_id.py`.
